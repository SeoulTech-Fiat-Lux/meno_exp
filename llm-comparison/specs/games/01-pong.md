# 퐁 요구사항

meno vs SFML 3 : LLM 생성 비교 실험

## 퐁 게임 개발

- 이 문서는 LLM 생성 비교 실험에 쓰는 미니게임 중 퐁의 요구사항을 정리함.
- 같은 명세를 meno 조건과 SFML 3.1 조건에 그대로 주며, LLM은 main.cpp 하나만 작성함.
- 창 제목은 "PADDLE BALL"임.
- 3차 요구사항의 '컴퓨터 대전'을 줄여, CPU를 상대로 혼자 플레이함.
- 색은 '화면 색' 절과 제공된 에셋을 따름.

## Major Functional Requirements

- 퐁의 주요 기능적 요구사항(Functional Requirement)은 다음과 같음.
  - 타이틀·플레이·결과로 이어지는 화면 흐름
  - 플레이어 패들 조작과 CPU 패들
  - 공의 반사, 득점과 승패
- 게임 실행 후 종료까지 거치는 기본 기능이며, 자세한 요구사항은 이어지는 절에서 설명함.

## Major Non-functional Requirements

- 주요 비기능적 요구사항(Non-Functional Requirement)은 다음과 같음.
  - 제공된 템플릿에서 main.cpp 한 파일로 오류 없이 빌드되어야 함.
  - 60 FPS 제한에서 프레임레이트와 무관하게 같은 속도로 진행해야 함.
  - 입력을 놓치지 않고 다음 갱신에 반영해야 함.
  - 입력 없이 실행해도 비정상 종료 없이 명세된 흐름을 보여야 함.
  - 공이 패들을 뚫거나 패들에 끼지 않아야 함.
- 자세한 요구사항은 이어지는 절에서 설명함.

## 화면 흐름과 공통 조작

- 창은 960×540이며, 제목 표시줄에는 "PADDLE BALL"을 표시해야 함.
- 화면은 타이틀 → 플레이 → 결과 순서로 진행함.
  - 타이틀: 게임 이름 "PADDLE BALL"(창 제목과 같음)과 "PRESS ENTER"를 표시. Enter를 누르거나 2초가 지나면 플레이 시작.
  - 결과: 결과 문구, 최종 점수, "R: RESTART  ESC: QUIT"를 표시.
- 결과 화면에서 R을 누르면 게임 상태를 모두 초기화하고(프로그램이 켜져 있는 동안 유지한다고 명세에 적힌 기록은 제외) 플레이를 다시 시작함 (타이틀은 거치지 않음).
- Esc는 어느 화면에서든 프로그램을 종료함. 창 닫기 버튼도 같음.
- 화면 문구는 영문 대문자이며, 명세에 적힌 문자열을 그대로 씀.
- 글자는 fonts/game.ttf로 그리며, 크기는 16의 배수(16·32·48px)로 함.
- 효과음은 명세에 지정된 사건에서, 지정된 파일로만 재생함.

## 구성과 조작

- 왼쪽에 플레이어 패들, 오른쪽에 CPU 패들, 가운데에 세로 점선을 그림. 화면 위쪽 가운데에서 중앙선 왼쪽에 플레이어 점수, 오른쪽에 CPU 점수를 표시함.
  - 가운데 점선은 폭 4, 길이 15의 막대를 x 478에 놓은 것이며, 막대 윗변의 y는 10, 40, 70, …처럼 30px마다임.
- 패들은 16×96 사각형이며, 왼쪽 위 꼭짓점의 x는 플레이어 32, CPU 912임. 두 패들 모두 세로 가운데에서 시작함.
- 공은 반지름 8의 원이며 화면 가운데에서 시작함.
- 플레이어 패들은 W 또는 ↑로 위, S 또는 ↓로 아래로 420 px/s로 움직임. 위아래 키를 함께 누르면 멈추며, 화면 위아래 밖으로 나가지 않음.
- CPU 패들은 0.15초마다 목표 y를 다시 정하고, 패들 중심 y가 목표를 향해 최대 300 px/s로 움직임. CPU 패들도 화면 위아래 밖으로 나가지 않음.
  - 공이 오른쪽(CPU 쪽)으로 움직이면 목표는 공의 y, 그렇지 않으면 화면 세로 가운데.

## 공과 점수

- 게임 시작과 득점 직후, 공은 가운데에서 1초 멈췄다가 출발함.
  - 첫 서브는 플레이어 쪽(왼쪽), 이후는 직전에 실점한 쪽으로 출발.
  - 각도는 수평에서 15°~30°(위·아래 무작위), 속력은 360 px/s.
- 위아래 벽에 닿으면 y 속도의 부호를 뒤집음.
- 패들에 닿으면 x 방향을 뒤집고, 반사각 = (공 중심 y − 패들 중심 y) ÷ 48 × 60°로 정함. 차이는 −48~48로 제한하며(최대 ±60°), 양수면 아래쪽으로 감. 속력은 패들 반사마다 5% 늘어 최대 720 px/s이며(벽 반사는 그대로), 반사 직후 공을 패들 바깥으로 옮김.
- 공이 왼쪽 끝을 완전히 넘으면 CPU, 오른쪽 끝을 완전히 넘으면 플레이어가 1점을 얻음.
- 먼저 5점을 얻으면 결과 화면으로 감. 문구는 "YOU WIN" 또는 "YOU LOSE", 점수는 "5 : 3" 형식(플레이어 : CPU).
- 패들·벽 반사 때 hit.wav, 득점 때 point.wav를 재생함.
- 플레이 중에는 bgm_pong.ogg를 볼륨 40%로 반복 재생하고, 결과 화면에서는 멈춤.

## 화면 색

- 배경: 검은색 #000000
- 패들, 공, 가운데 점선: 흰색 #FFFFFF
- 글자: 흰색 #FFFFFF
- 텍스처가 있는 요소는 텍스처의 색을 그대로 씀.

## 판정과 무입력 실행

- 공은 어떤 속력에서도 패들을 뚫고 지나가지 않아야 함. (최대 720 px/s = 틱당 12px < 패들 두께 16px)
- 공이 패들 안에 끼어 연속으로 반사되는 일이 없어야 함.
- 무입력 실행: 첫 서브가 멈춰 있는 플레이어 패들을 지나 CPU가 득점하고, 10초 안에 CPU 점수가 2점 이상이어야 함.
  - 예상 흐름 (실행 시작 기준, 근사값): 0초 타이틀 → 2초 플레이 시작 → 3초 첫 서브(왼쪽) → 약 4.5초 CPU 1점 → 약 7초 CPU 2점

## 코드와 빌드

- 코드는 main.cpp 한 파일이며, 제공된 CMakeLists.txt와 assets/는 수정하지 않음.
- meno 조건은 meno 공개 헤더만 쓰고 SFML 헤더를 직접 include하지 않음. SFML 조건은 SFML 3.1 모듈만 씀. 두 조건 모두 C++20 표준 라이브러리 외의 라이브러리는 쓰지 않음.
- 기준 환경에서 오류 없이 빌드되어야 함.
- 에셋을 읽지 못하면 실패한 경로를 표준 에러에 출력하고 종료 코드 1로 끝내야 함.

## 실행 품질

- 프레임은 60 FPS로 제한함. 모든 속도와 시간은 초 단위이며, 프레임레이트가 달라져도 게임 진행 속도는 같아야 함.
- 키와 마우스 입력은 다음 갱신에 반영하며, 한 프레임보다 짧게 눌렀다 뗀 입력도 놓치지 않아야 함.
- 입력 없이 10초 실행하는 동안 비정상 종료나 처리되지 않은 예외가 없어야 함. Esc나 창 닫기로 끝나면 종료 코드 0.
- 기준 환경에서 프레임 시간 95백분위가 20ms 이하여야 함.
  - 이 항목은 측정 하니스로만 확인함 (플레이 채점 제외).

## 게임 실행 환경

- 기준 환경: Ubuntu 24.04, GCC 13.3, CMake 3.28 이상
- SFML 3.1.0 (meno의 백엔드와 같은 버전)
- 화면 없는 실행은 xvfb-run을 씀.
- 제공물: 조건별 CMakeLists.txt 템플릿과 공통 assets/ 폴더. 두 조건이 같은 에셋을 씀.
- 에셋은 상대 경로 assets/…로 엶. 실행 파일은 assets/와 같은 폴더에 있으며, 그 폴더를 작업 디렉터리로 하여 실행함.
- 이 게임이 쓰는 에셋 (assets/…):
  - fonts/game.ttf
  - sfx/hit.wav
  - sfx/point.wav
  - music/bgm_pong.ogg

## 주의 사항

- 명세의 수치와 문자열은 정확히 따라야 함.
- 색과 그림은 명세와 제공된 에셋에 정한 것을 씀.
- 명세가 모호하면 가장 단순한 해석을 택함.
