# 고정 화면 슈팅 요구사항

meno vs SFML 3 : LLM 생성 비교 실험

## 고정 화면 슈팅 게임 개발

- 이 문서는 LLM 생성 비교 실험에 쓰는 미니게임 중 고정 화면 슈팅의 요구사항을 정리함.
- 같은 명세를 meno 조건과 SFML 3.1 조건에 그대로 주며, LLM은 main.cpp 하나만 작성함.
- 창 제목은 "STAR FORMATION"임.
- 좌우로 움직이며 내려오는 적 대열을 아래쪽 포대로 쏘아 없애는 게임임.
- 색은 '화면 색' 절과 제공된 에셋을 따름.

## Major Functional Requirements

- 고정 화면 슈팅의 주요 기능적 요구사항(Functional Requirement)은 다음과 같음.
  - 타이틀·플레이·결과로 이어지는 화면 흐름
  - 적 대열의 이동, 가속, 조준 사격
  - 플레이어 포대와 사격
  - 방어벽, 보너스 비행체, 목숨과 웨이브
- 게임 실행 후 종료까지 거치는 기본 기능이며, 자세한 요구사항은 이어지는 절에서 설명함.

## Major Non-functional Requirements

- 주요 비기능적 요구사항(Non-Functional Requirement)은 다음과 같음.
  - 제공된 템플릿에서 main.cpp 한 파일로 오류 없이 빌드되어야 함.
  - 60 FPS 제한에서 프레임레이트와 무관하게 같은 속도로 진행해야 함.
  - 입력을 놓치지 않고 다음 갱신에 반영해야 함.
  - 입력 없이 실행해도 비정상 종료 없이 명세된 흐름을 보여야 함.
  - 총알이 방어벽 조각을 건너뛰지 않고, 없어진 오브젝트가 남지 않아야 함.
- 자세한 요구사항은 이어지는 절에서 설명함.

## 화면 흐름과 공통 조작

- 창은 960×540이며, 제목 표시줄에는 "STAR FORMATION"을 표시해야 함.
- 화면은 타이틀 → 플레이 → 결과 순서로 진행함.
  - 타이틀: 게임 이름 "STAR FORMATION"(창 제목과 같음)과 "PRESS ENTER"를 표시. Enter를 누르거나 2초가 지나면 플레이 시작.
  - 결과: 결과 문구, 최종 점수, "R: RESTART  ESC: QUIT"를 표시.
- 결과 화면에서 R을 누르면 게임 상태를 모두 초기화하고(프로그램이 켜져 있는 동안 유지한다고 명세에 적힌 기록은 제외) 플레이를 다시 시작함 (타이틀은 거치지 않음).
- Esc는 어느 화면에서든 프로그램을 종료함. 창 닫기 버튼도 같음.
- 화면 문구는 영문 대문자이며, 명세에 적힌 문자열을 그대로 씀.
- 글자는 fonts/game.ttf로 그리며, 크기는 16의 배수(16·32·48px)로 함.
- 효과음은 명세에 지정된 사건에서, 지정된 파일로만 재생함.

## 적 대열

- 적은 8열×4행 32마리이며, 각 적은 32×24임. 웨이브 1에서 c열 r행(0부터 셈) 적의 왼쪽 위는 (296 + 48c, 80 + 40r)임.
- 그림은 fm_enemies.png(192×24)의 32×24 여섯 칸을 씀. 0행 적은 0~1번 칸(30점), 1행은 2~3번 칸(20점), 2~3행은 4~5번 칸(10점)이며, 0.5초마다 두 칸을 번갈아 씀.
- 대열은 처음에 오른쪽으로 움직이며, 속력은 40 + 4 × (32 − 남은 적 수) px/s임.
- 대열의 가장 바깥 적이 x 16 또는 x 944에 닿으면, 대열 전체가 16px 내려오고 좌우 방향을 바꿈.
- 웨이브 시작 1초 뒤부터 1초마다 적 하나가 탄을 쏨. 쏘는 적은 적이 남은 열 중 플레이어 중심과 x 거리가 가장 가까운 열(같으면 왼쪽 열)의 맨 아래 적이며, 탄은 그 적의 아래쪽 가운데에서 그 순간의 플레이어 중심을 향해 240 px/s로 날아감. 적 탄은 반지름 3의 원이고, 동시에 3개까지만 있을 수 있음.

## 플레이어와 방어벽

- 플레이어는 fm_player.png(40×24)로 그리며, 위쪽 y 490, 가로 가운데에서 시작함. ←·A, →·D로 300 px/s 움직이고, 화면 좌우 16px 안쪽에 머묾.
- Space를 누른 순간 4×12 총알을 위로 600 px/s로 쏘고 shoot.wav를 재생함. 플레이어 총알은 동시에 하나만 있을 수 있음.
- 방어벽 4개를 가로 중심 192, 384, 576, 768, 위쪽 y 400에 둠. 방어벽 하나는 8×8 조각 6열×4행(48×32)으로 이루어짐.
- 플레이어 총알이나 적 탄이 방어벽 조각에 닿으면 그 조각과 탄이 함께 없어짐. 적이 방어벽 조각에 겹치면 그 조각이 없어짐.

## 점수와 웨이브

- 플레이어 총알이 적에 맞으면 둘 다 없어지고 점수를 얻으며 hit.wav를 재생함.
- 플레이 시작부터 20초마다 보너스 비행체 fm_bonus.png(48×20)가 위쪽 y 50에서, 화면 밖(왼쪽 위 x −48 또는 960)을 왼쪽부터 번갈아 출발해 120 px/s로 가로지르며, 반대편 화면 밖으로 완전히 나가면 없어짐. 맞히면 50, 100, 150점 중 무작위로 얻고 bonus.wav를 재생함.
- 적 탄이 플레이어에 맞으면 목숨을 하나 잃고 lose.wav를 재생함. 화면의 모든 탄을 없애고 1초 동안 모두 멈춘 뒤 이어서 진행함. 목숨이 0이 되면 멈추지 않고 바로 결과 화면으로 감.
- 적을 모두 없애면 다음 웨이브로 감. 대열은 처음 위치보다 16 × (웨이브 − 1)px 아래(최대 64px)에서 다시 오른쪽으로 움직이기 시작하고, 방어벽은 다시 채움. 화면의 모든 탄과 보너스 비행체는 없앰.
- 화면 위쪽에 "SCORE n", "WAVE n", "LIVES n"을 표시함. 목숨은 3개로 시작함.
- 목숨이 0이 되거나 적이 y 490에 닿으면 결과 화면으로 감. 문구는 "GAME OVER", "SCORE n", "WAVE n".
- 플레이 중에는 bgm_formation.ogg를 볼륨 40%로 반복 재생하고, 결과 화면에서는 멈춤.
- 그리는 순서는 방어벽 → 적 → 보너스 비행체 → 플레이어 → 탄 → 점수임.

## 화면 색

- 배경: 검은색 #000000
- 방어벽 조각: #4CC26B
- 플레이어 총알: 흰색 #FFFFFF
- 적 탄: #FF6B6B
- 글자: 흰색 #FFFFFF
- 텍스처가 있는 요소는 텍스처의 색을 그대로 씀.

## 판정과 무입력 실행

- 플레이어 총알이 방어벽 조각을 건너뛰지 않아야 함. (틱당 10px < 총알 길이 12px + 조각 8px)
- 없어진 적, 조각, 탄은 남지 않고 삭제되어야 함. 웨이브가 끝나면 적과 탄 수가 0이어야 함.
- 대열이 내려오며 방향을 바꾸는 일은 가장자리에 닿을 때마다 한 번만 일어나야 함.
- 무입력 실행: 적 탄이 방어벽 사이 틈으로 가운데의 플레이어를 맞히고, 목숨을 모두 잃어 20초 안에 결과 화면으로 가야 함.
  - 예상 흐름 (실행 시작 기준, 근사값): 0초 타이틀 → 2초 웨이브 1 시작 → 3초 첫 적 탄 → 약 4초 첫 피격 → 20초 안에 결과 화면

## 코드와 빌드

- 코드는 main.cpp 한 파일이며, 제공된 CMakeLists.txt와 assets/는 수정하지 않음.
- meno 조건은 meno 공개 헤더만 쓰고 SFML 헤더를 직접 include하지 않음. SFML 조건은 SFML 3.1 모듈만 씀. 두 조건 모두 C++20 표준 라이브러리 외의 라이브러리는 쓰지 않음.
- 기준 환경에서 오류 없이 빌드되어야 함.
- 에셋을 읽지 못하면 실패한 경로를 표준 에러에 출력하고 종료 코드 1로 끝내야 함.

## 실행 품질

- 프레임은 60 FPS로 제한함. 모든 속도와 시간은 초 단위이며, 프레임레이트가 달라져도 게임 진행 속도는 같아야 함.
- 키와 마우스 입력은 다음 갱신에 반영하며, 한 프레임보다 짧게 눌렀다 뗀 입력도 놓치지 않아야 함.
- 입력 없이 10초 실행하는 동안 비정상 종료나 처리되지 않은 예외가 없어야 함. Esc나 창 닫기로 끝나면 종료 코드 0.
- 기준 환경에서 프레임 시간 95백분위가 20ms 이하여야 함.
  - 이 항목은 측정 하니스로만 확인함 (플레이 채점 제외).

## 게임 실행 환경

- 기준 환경: Ubuntu 24.04, GCC 13.3, CMake 3.28 이상
- SFML 3.1.0 (meno의 백엔드와 같은 버전)
- 화면 없는 실행은 xvfb-run을 씀.
- 제공물: 조건별 CMakeLists.txt 템플릿과 공통 assets/ 폴더. 두 조건이 같은 에셋을 씀.
- 에셋은 상대 경로 assets/…로 엶. 실행 파일은 assets/와 같은 폴더에 있으며, 그 폴더를 작업 디렉터리로 하여 실행함.
- 텍스처는 제공된 크기 그대로 게임 안에서 그림.

## 제공 에셋

- 이 게임이 쓰는 에셋 (assets/…):
  - fonts/game.ttf
  - sfx/shoot.wav, sfx/hit.wav
  - sfx/lose.wav, sfx/bonus.wav
  - music/bgm_formation.ogg
  - textures/fm_enemies.png (192×24), textures/fm_player.png (40×24), textures/fm_bonus.png (48×20)

## 주의 사항

- 명세의 수치와 문자열은 정확히 따라야 함.
- 색과 그림은 명세와 제공된 에셋에 정한 것을 씀.
- 명세가 모호하면 가장 단순한 해석을 택함.
