# 플래피류 요구사항

meno vs SFML 3 : LLM 생성 비교 실험

## 플래피류 게임 개발

- 이 문서는 LLM 생성 비교 실험에 쓰는 미니게임 중 플래피류의 요구사항을 정리함.
- 같은 명세를 meno 조건과 SFML 3.1 조건에 그대로 주며, LLM은 main.cpp 하나만 작성함.
- 창 제목은 "SKY GATES"임.
- 색은 '화면 색' 절과 제공된 에셋을 따름.

## Major Functional Requirements

- 플래피류의 주요 기능적 요구사항(Functional Requirement)은 다음과 같음.
  - 타이틀·플레이·결과로 이어지는 화면 흐름
  - 새의 중력, 날갯짓, 기울기
  - 기둥의 생성·이동·삭제와 점수
  - 충돌과 결과 화면
- 게임 실행 후 종료까지 거치는 기본 기능이며, 자세한 요구사항은 이어지는 절에서 설명함.

## Major Non-functional Requirements

- 주요 비기능적 요구사항(Non-Functional Requirement)은 다음과 같음.
  - 제공된 템플릿에서 main.cpp 한 파일로 오류 없이 빌드되어야 함.
  - 60 FPS 제한에서 프레임레이트와 무관하게 같은 속도로 진행해야 함.
  - 입력을 놓치지 않고 다음 갱신에 반영해야 함.
  - 입력 없이 실행해도 비정상 종료 없이 명세된 흐름을 보여야 함.
  - 오래 플레이해도 오브젝트 수가 늘지 않고, 충돌 판정이 명세의 충돌 영역과 맞아야 함.
- 자세한 요구사항은 이어지는 절에서 설명함.

## 화면 흐름과 공통 조작

- 창은 960×540이며, 제목 표시줄에는 "SKY GATES"을 표시해야 함.
- 화면은 타이틀 → 플레이 → 결과 순서로 진행함.
  - 타이틀: 게임 이름 "SKY GATES"(창 제목과 같음)과 "PRESS ENTER"를 표시. Enter를 누르거나 2초가 지나면 플레이 시작.
  - 결과: 결과 문구, 최종 점수, "R: RESTART  ESC: QUIT"를 표시.
- 결과 화면에서 R을 누르면 게임 상태를 모두 초기화하고(프로그램이 켜져 있는 동안 유지한다고 명세에 적힌 기록은 제외) 플레이를 다시 시작함 (타이틀은 거치지 않음).
- Esc는 어느 화면에서든 프로그램을 종료함. 창 닫기 버튼도 같음.
- 화면 문구는 영문 대문자이며, 명세에 적힌 문자열을 그대로 씀.
- 글자는 assets/fonts/game.ttf로 그리며, 크기는 16의 배수(16·32·48px)로 함.
- 효과음은 명세에 지정된 사건에서, 지정된 파일로만 재생함.

## 새와 화면

- 새는 assets/textures/bird.png(32×24, 오른쪽을 향한 그림)로 그림. 그림 중심의 x는 240에 고정되며, 그림 중심의 y는 270에서 시작함. 충돌 영역은 그림 중심에 둔 반지름 10의 원임.
- 중력 가속도는 아래쪽으로 1500 px/s²임. Space, W, ↑ 중 하나를 누른 순간 세로 속도를 위쪽 480 px/s로 바꾸고 assets/sfx/flap.wav를 재생함.
- 새는 (세로 속도 ÷ 10)°만큼 그림 중심을 기준으로 기울임. −30°~90°로 제한하며, 시계 방향이 양수임.
- 새의 충돌 원은 화면 위로 나가지 않으며, 막힐 때 세로 속도를 0으로 함. 바닥은 y=500부터 높이 40의 띠임.
- 그리는 순서는 배경(assets/textures/background.png) → 기둥 → 바닥 → 새 → 점수임.
- 플레이 중에는 assets/music/bgm_flappy.ogg를 볼륨 40%로 반복 재생하고, 결과 화면에서는 멈춤.

## 기둥과 점수

- 기둥 한 쌍은 assets/textures/gate.png(64×400) 두 장으로 만듦. 아래 기둥은 그대로, 위 기둥은 세로로 뒤집어 그리며, 두 기둥 사이의 틈은 150px임.
- 틈의 중심 y는 140~400 사이에서 무작위로 정함. 기둥 쌍은 플레이 시작 1초 뒤부터 1.6초마다 화면 오른쪽 밖(x=960)에 생기고, 왼쪽으로 180 px/s로 움직임.
- 화면 왼쪽 밖으로 완전히 나간 기둥 쌍은 삭제함.
- 새가 기둥이나 바닥에 닿으면 assets/sfx/lose.wav를 재생하고 결과 화면으로 감. 기둥의 충돌 영역은 그림과 같은 사각형임.
- 새 중심의 x가 기둥 쌍의 오른쪽 끝을 지나면 1점을 얻고 assets/sfx/point.wav를 재생함. 점수는 숫자만(예: "3") 화면 위 가운데에 표시함.
- 결과 화면에는 "GAME OVER", "SCORE n", "BEST m"을 표시함. BEST는 프로그램이 켜져 있는 동안의 최고 점수임.

## 화면 색

- 배경: assets/textures/background.png를 그대로 씀
- 바닥 띠: #3B3747
- 글자: 흰색 #FFFFFF, 검은색 #000000 외곽선 2px
- 텍스처가 있는 요소는 텍스처의 색을 그대로 씀.

## 판정과 무입력 실행

- 기둥 쌍은 동시에 5쌍을 넘지 않아야 함. 오래 플레이해도 오브젝트 수가 늘지 않아야 함.
- 충돌 판정은 명세의 충돌 영역(새는 반지름 10 원, 기둥은 64×400 사각형, 바닥은 y 500 아래)과 일치해야 함. 이 영역끼리 닿지 않았는데 끝나거나, 겹쳤는데 지나가는 일이 없어야 함.
- 무입력 실행: 새가 떨어져 바닥에 닿고 결과 화면으로 가야 함.
  - 예상 흐름 (실행 시작 기준, 근사값): 0초 타이틀 → 2초 플레이 시작, 낙하 → 약 2.5초 바닥 충돌, 결과 화면

## 코드와 빌드

- 코드는 main.cpp 한 파일이며, 제공된 CMakeLists.txt와 assets/는 수정하지 않음.
- meno 조건은 meno 공개 헤더만 쓰고 SFML 헤더를 직접 include하지 않음. SFML 조건은 SFML 3.1 모듈만 씀. 두 조건 모두 C++20 표준 라이브러리 외의 라이브러리는 쓰지 않음.
- 기준 환경에서 오류 없이 빌드되어야 함.
- 에셋을 읽지 못하면 실패한 경로를 표준 에러에 출력하고 종료 코드 1로 끝내야 함.

## 실행 품질

- 프레임은 60 FPS로 제한함. 모든 속도와 시간은 초 단위이며, 프레임레이트가 달라져도 게임 진행 속도는 같아야 함.
- 키와 마우스 입력은 다음 갱신에 반영하며, 한 프레임보다 짧게 눌렀다 뗀 입력도 놓치지 않아야 함.
- 입력 없이 10초 실행하는 동안 비정상 종료나 처리되지 않은 예외가 없어야 함. Esc나 창 닫기로 끝나면 종료 코드 0.
- 기준 환경에서 프레임 시간 95백분위가 20ms 이하여야 함.
  - 이 항목은 측정 하니스로만 확인함 (플레이 채점 제외).

## 게임 실행 환경

- 기준 환경: Ubuntu 24.04, GCC 13.3, CMake 3.28 이상
- SFML 3.1.0 (meno의 백엔드와 같은 버전)
- 화면 없는 실행은 xvfb-run을 씀.
- 제공물: 조건별 CMakeLists.txt 템플릿과 공통 assets/ 폴더. 두 조건이 같은 에셋을 씀.
- 에셋은 상대 경로 assets/…로 엶. 실행 파일은 assets/와 같은 폴더에 있으며, 그 폴더를 작업 디렉터리로 하여 실행함.
- 텍스처는 제공된 크기 그대로 게임 안에서 그림.

## 제공 에셋

- 이 게임이 쓰는 에셋:
  - assets/fonts/game.ttf
  - assets/sfx/point.wav
  - assets/sfx/lose.wav
  - assets/sfx/flap.wav
  - assets/music/bgm_flappy.ogg
  - assets/textures/background.png (960×540)
  - assets/textures/bird.png (32×24)
  - assets/textures/gate.png (64×400)

## 주의 사항

- 명세의 수치와 문자열은 정확히 따라야 함.
- 색과 그림은 명세와 제공된 에셋에 정한 것을 씀.
- 명세가 모호하면 가장 단순한 해석을 택함.
