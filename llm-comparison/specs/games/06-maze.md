# 팩맨류 요구사항

meno vs SFML 3 : LLM 생성 비교 실험

## 팩맨류 게임 개발

- 이 문서는 LLM 생성 비교 실험에 쓰는 미니게임 중 팩맨류의 요구사항을 정리함.
- 같은 명세를 meno 조건과 SFML 3.1 조건에 그대로 주며, LLM은 main.cpp 하나만 작성함.
- 창 제목은 "MAZE CHASE"임.
- 격자 미로의 점을 모두 먹으며 추격자 4마리를 피하는 게임임.
- 색은 '화면 색' 절과 제공된 에셋을 따름.

## Major Functional Requirements

- 팩맨류의 주요 기능적 요구사항(Functional Requirement)은 다음과 같음.
  - 타이틀·플레이·결과로 이어지는 화면 흐름
  - 고정된 미로와 점·파워 알
  - 플레이어의 칸 단위 이동과 방향 기억
  - 추격자 4마리의 추적·겁먹음·복귀
  - 목숨, 레벨, 점수
- 게임 실행 후 종료까지 거치는 기본 기능이며, 자세한 요구사항은 이어지는 절에서 설명함.

## Major Non-functional Requirements

- 주요 비기능적 요구사항(Non-Functional Requirement)은 다음과 같음.
  - 제공된 템플릿에서 main.cpp 한 파일로 오류 없이 빌드되어야 함.
  - 60 FPS 제한에서 프레임레이트와 무관하게 같은 속도로 진행해야 함.
  - 입력을 놓치지 않고 다음 갱신에 반영해야 함.
  - 입력 없이 실행해도 비정상 종료 없이 명세된 흐름을 보여야 함.
  - 플레이어와 추격자가 벽을 뚫지 않고, 추격자의 경로가 명세대로 정해져야 함.
- 자세한 요구사항은 이어지는 절에서 설명함.

## 화면 흐름과 공통 조작

- 창은 960×540이며, 제목 표시줄에는 "MAZE CHASE"을 표시해야 함.
- 화면은 타이틀 → 플레이 → 결과 순서로 진행함.
  - 타이틀: 게임 이름 "MAZE CHASE"(창 제목과 같음)과 "PRESS ENTER"를 표시. Enter를 누르거나 2초가 지나면 플레이 시작.
  - 결과: 결과 문구, 최종 점수, "R: RESTART  ESC: QUIT"를 표시.
- 결과 화면에서 R을 누르면 게임 상태를 모두 초기화하고(프로그램이 켜져 있는 동안 유지한다고 명세에 적힌 기록은 제외) 플레이를 다시 시작함 (타이틀은 거치지 않음).
- Esc는 어느 화면에서든 프로그램을 종료함. 창 닫기 버튼도 같음.
- 화면 문구는 영문 대문자이며, 명세에 적힌 문자열을 그대로 씀.
- 글자는 fonts/game.ttf로 그리며, 크기는 16의 배수(16·32·48px)로 함.
- 효과음은 명세에 지정된 사건에서, 지정된 파일로만 재생함.

## 미로와 화면

- 미로는 이어지는 절의 21×21 문자 지도를 그대로 씀. 한 칸은 22×22px이며, 지도의 왼쪽 위 칸을 화면 (249, 40)에 놓음.
- 기호: # 벽, . 점, o 파워 알, _ 빈 통로, P 플레이어 시작 칸, G 추격자 집, - 집 문, T 터널. 터널은 왼쪽 끝과 오른쪽 끝이 이어짐. 집(G)과 집 문(-)은 벽처럼 지나갈 수 없음 (2~4번이 집에서 나오는 것만 예외).
- 벽은 칸을 채운 사각형, 점은 반지름 2, 파워 알은 반지름 6의 원으로 그림. 파워 알은 0.25초마다 보였다 사라짐. 집 문은 문 칸의 세로 가운데에 22×4 막대로 그림.
- 화면 위쪽에 "SCORE n"과 "BEST m", 아래쪽에 남은 목숨 수만큼의 플레이어 그림과 "LEVEL n"을 표시함. BEST는 프로그램이 켜져 있는 동안의 최고 점수이며, 점수가 BEST를 넘으면 BEST도 바로 같이 오름.
- 레벨을 시작할 때와 목숨을 잃은 뒤에는 미로 가운데에 "READY"를 2초 표시하며, 그동안 모두 멈춤.
- 플레이 중에는 bgm_maze.ogg를 볼륨 40%로 반복 재생하고, 결과 화면에서는 멈춤.

- 플레이어 시작: 15행 10열. 집 문: 8행 10열. 문 위 칸: 7행 10열.

## 플레이어

- 플레이어는 maze_player.png(48×24)로 그림. 24×24 두 칸이며 0번은 입을 벌린 모습, 1번은 다문 모습임. 움직이는 동안 0.1초마다 두 칸을 번갈아 씀.
- 그림은 오른쪽을 향하며, 이동 방향에 맞춰 회전함 (오른쪽 0°, 아래 90°, 왼쪽 180°, 위 270°).
- 방향키와 WASD로 조작함. 속력은 초당 6칸이며, 칸 중심에서만 방향을 바꿈.
  - 막힌 방향을 누르면 기억했다가, 그쪽으로 갈 수 있는 첫 칸 중심에서 바꿈. 정반대 방향은 바로 바꿈.
  - 레벨 시작과 목숨을 잃은 뒤에는 왼쪽으로 움직이기 시작하며, 벽에 막히면 멈춤.
- 점을 먹으면 10점과 chomp.wav, 파워 알을 먹으면 50점과 power.wav. 파워 알을 먹으면 집 밖에 있고 눈 상태가 아닌 추격자가 6초 동안 겁먹음. 이미 겁먹은 추격자는 6초를 처음부터 다시 셈.
- 점과 파워 알을 모두 먹으면 다음 레벨로 감. 미로를 다시 채우고, 모두 시작 위치로 돌아가 겁먹음과 눈 상태를 풀고 READY부터 시작함. 레벨 n의 추격자 기본 속력은 초당 5 × (1 + 0.1 × (n − 1))칸이며 최대 7.5칸임.

## 추격자의 이동

- 추격자 4마리는 maze_chasers.png(144×24)로 그림. 24×24 여섯 칸이며 0~3번은 각 추격자, 4번은 겁먹은 모습, 5번은 잡아먹혀 눈만 남은 모습임.
- 1번은 집 문 위 칸(7행 10열)에서 왼쪽을 향해 시작함. 2·3·4번은 집 안 9행 9·10·11열에 멈춰 있다가, READY가 끝나고 3초, 6초, 9초가 되면 문 위 칸 중심에 나타나 위를 향한 채 아래 규칙으로 움직임.
- 기본 속력은 레벨 1에서 초당 5칸임. 칸 중심에 올 때마다 갈 수 있는 방향 중, 그 방향으로 한 칸 간 칸과 목표 칸 중심 사이의 직선 거리가 가장 짧은 방향을 고르며, 같으면 위·왼쪽·아래·오른쪽 순으로 정함. 방금 온 방향으로는 되돌아가지 않음.
- 목표 칸은 추격자마다 다름.
  - 1번: 플레이어 칸. 2번: 플레이어 진행 방향으로 4칸 앞.
  - 3번: 목표 없이 칸 중심마다 갈 수 있는 방향 중 무작위 (방금 온 방향은 뺌).
  - 4번: 자기 칸과 플레이어 칸의 직선 거리가 8칸 이상이면 플레이어 칸, 아니면 19행 1열.

## 겁먹음과 목숨

- 겁먹은 추격자는 초당 3칸으로 움직이고 칸 중심마다 갈 수 있는 방향 중 무작위로 고름 (방금 온 방향은 뺌). 겁먹기 시작할 때 진행 방향을 반대로 바꾸며, 마지막 2초는 0.2초마다 4번 칸과 원래 칸을 번갈아 보여 줌.
- 겁먹은 추격자에 닿으면 잡아먹음. 파워 알 하나로 잡아먹을 때마다 200, 400, 800, 1600점을 차례로 얻고 eat.wav를 재생함.
- 잡아먹힌 추격자는 눈만 남아, 같은 방향 규칙으로 문 위 칸을 목표로 초당 10칸 이동함. 도착하면 겁먹지 않은 상태로 다시 움직임.
- 겁먹지 않은 추격자에 닿으면 목숨을 하나 잃고 lose.wav를 재생함. 모두 시작 위치로 돌아가 겁먹음과 눈 상태를 풀고 READY부터 다시 시작함. 닿음 판정은 두 중심의 거리가 12px보다 작을 때임.
- 목숨은 3개로 시작하며, 0이 되면 결과 화면으로 감. 문구는 "GAME OVER", "SCORE n", "LEVEL n".

## 화면 색

- 배경: 검은색 #000000
- 벽: #1FA2A8
- 점, 파워 알: #FFF3D6
- 집 문: #C9D1DC
- 글자: 흰색 #FFFFFF, "READY"만 #FFD54A
- 텍스처가 있는 요소는 텍스처의 색을 그대로 씀.

## 경로와 무입력 실행

- 플레이어와 추격자의 중심은 벽·집·집 문 칸에 들어가지 않아야 함 (집에서 기다리는 2~4번 제외). 모든 이동은 통로 칸의 중심을 잇는 선 위에서만 일어남.
- 칸 중심에 닿기 직전에 누른 방향도 그 칸에서 반영되어야 함 (방향 기억).
- 1·2·4번 추격자의 경로는 같은 상황이면 매번 같아야 함. 무작위는 3번과 겁먹은 추격자에만 씀.
- 무입력 실행: 플레이어가 왼쪽으로 5칸 가서 멈추고 1번 추격자에게 잡힘. 목숨 3개를 모두 잃고 20초 안에 결과 화면으로 가야 함.
  - 예상 흐름 (실행 시작 기준, 근사값): 0초 타이틀 → 2초 READY → 4초 플레이 시작 → 약 6.5초 첫 목숨 → 약 11초 둘째 → 약 15.5초 결과 화면

## 코드와 빌드

- 코드는 main.cpp 한 파일이며, 제공된 CMakeLists.txt와 assets/는 수정하지 않음.
- meno 조건은 meno 공개 헤더만 쓰고 SFML 헤더를 직접 include하지 않음. SFML 조건은 SFML 3.1 모듈만 씀. 두 조건 모두 C++20 표준 라이브러리 외의 라이브러리는 쓰지 않음.
- 기준 환경에서 오류 없이 빌드되어야 함.
- 에셋을 읽지 못하면 실패한 경로를 표준 에러에 출력하고 종료 코드 1로 끝내야 함.

## 실행 품질

- 프레임은 60 FPS로 제한함. 모든 속도와 시간은 초 단위이며, 프레임레이트가 달라져도 게임 진행 속도는 같아야 함.
- 키와 마우스 입력은 다음 갱신에 반영하며, 한 프레임보다 짧게 눌렀다 뗀 입력도 놓치지 않아야 함.
- 입력 없이 10초 실행하는 동안 비정상 종료나 처리되지 않은 예외가 없어야 함. Esc나 창 닫기로 끝나면 종료 코드 0.
- 기준 환경에서 프레임 시간 95백분위가 20ms 이하여야 함.
  - 이 항목은 측정 하니스로만 확인함 (플레이 채점 제외).

## 게임 실행 환경

- 기준 환경: Ubuntu 24.04, GCC 13.3, CMake 3.28 이상
- SFML 3.1.0 (meno의 백엔드와 같은 버전)
- 화면 없는 실행은 xvfb-run을 씀.
- 제공물: 조건별 CMakeLists.txt 템플릿과 공통 assets/ 폴더. 두 조건이 같은 에셋을 씀.
- 에셋은 상대 경로 assets/…로 엶. 실행 파일은 assets/와 같은 폴더에 있으며, 그 폴더를 작업 디렉터리로 하여 실행함.
- 텍스처는 제공된 크기 그대로 게임 안에서 그림.

## 제공 에셋

- 이 게임이 쓰는 에셋 (assets/…):
  - fonts/game.ttf
  - sfx/chomp.wav
  - sfx/power.wav
  - sfx/eat.wav
  - sfx/lose.wav
  - music/bgm_maze.ogg
  - textures/maze_player.png (48×24)
  - textures/maze_chasers.png (144×24)

## 주의 사항

- 명세의 수치와 문자열은 정확히 따라야 함.
- 색과 그림은 명세와 제공된 에셋에 정한 것을 씀.
- 명세가 모호하면 가장 단순한 해석을 택함.
