# 미니게임 실험 운영

meno vs SFML 3 : LLM 생성 비교 실험

## 실험 목표(퐁)

- 목적: 가장 쉬운 기준선. 여기서 나오는 실패는 대부분 API 사용 오류이므로, 두 조건의 차이가 그대로 드러남.
- 검증 기능: 키 상태 입력, 두 키 세트 매핑, 원-사각형 충돌, 텍스트, 효과음·배경음, 화면 전환
- 난이도 하, 예상 분량 150~250줄. 게임별 기능 요구사항 12개, 비기능 요구사항 3개 (공통 요구사항 별도).

## 실험 목표(스네이크)

- 목적: 대조군. 격자 논리 위주라 씬·충돌 기능을 거의 쓰지 않으므로, 두 조건의 차이가 작게 나오는 것이 정상일 수 있음.
- 검증 기능: 키를 누른 순간의 입력, 고정 간격 이동, 도형·텍스트 그리기, 효과음·배경음, 화면 전환
- 난이도 하, 예상 분량 120~220줄. 게임별 기능 요구사항 10개, 비기능 요구사항 3개 (공통 요구사항 별도).

## 실험 목표(플래피류)

- 목적: 플레이 중 오브젝트 생성·삭제, 그리기 순서, 텍스처 스프라이트(뒤집기·회전)를 검증함.
- 검증 기능: 키를 누른 순간의 입력, 세 키 매핑, 원-사각형 충돌, 스프라이트·레이어, 화면 전환, 효과음·배경음
- 난이도 중하, 예상 분량 200~300줄. 게임별 기능 요구사항 12개, 비기능 요구사항 3개 (공통 요구사항 별도).

## 실험 목표(탑다운 슈터)

- 목적: 상한선. 가장 많은 기능을 한 게임에서 쓰므로 두 조건의 차이가 가장 크게 날 것으로 예상함.
- 검증 기능: 키·마우스 입력, 키 매핑, 회전, 대량 생성·삭제, 원-원 다대다 충돌, 카메라 추적, 화면↔월드 좌표 변환, 레터박스, 화면 고정 UI, 효과음·배경음, 텍스처 공유
- 난이도 중, 예상 분량 300~450줄. 게임별 기능 요구사항 16개, 비기능 요구사항 6개 (공통 요구사항 별도).

## 실험 목표(카드 짝 맞추기)

- 목적: (선택 게임) 나머지 넷이 다루지 않는 마우스 클릭 판정과 텍스트 입력을 검증함. 물리 없는 UI 중심 게임임.
- 검증 기능: 마우스 클릭, 점-사각형 판정, 스프라이트 시트 부분 그리기, 텍스트 입력, 레터박스에서의 클릭 좌표 변환, 타이머, 효과음·배경음, 화면 전환
- 난이도 중하, 예상 분량 200~300줄. 게임별 기능 요구사항 13개, 비기능 요구사항 3개 (공통 요구사항 별도).

## 실험 목표(팩맨류)

- 목적: 격자·논리 중심의 기준선. 팀원이 한 줄 지시만으로 만든 결과물이 있어, 명세를 준 경우와 비교할 수 있음.
- 검증 기능: 키 입력과 방향 기억, 액션 매핑, 칸 단위 이동, 상태 전환(READY·겁먹음·레벨), 스프라이트 시트 애니메이션과 회전, 텍스트, 효과음·배경음, 화면 전환
- 난이도 중, 예상 분량 400~600줄. 게임별 기능 요구사항 20개, 비기능 요구사항 4개 (공통 요구사항 별도).

## 실험 목표(소행성 슈팅)

- 목적: 회전과 관성 이동, 화면 끝 이어짐, 운석 분열로 인한 대량 생성·삭제를 검증함. 운석을 다각형으로 그려야 하므로, #35에서 보완한 다각형 외곽선 그리기의 검증 대상이기도 함.
- 검증 기능: 누른 순간·누르고 있는 키 입력, 회전, 관성, 화면 끝 이어짐, 원 충돌, 대량 생성·삭제, 선으로 그린 다각형, 깜빡임, 효과음·배경음, 화면 전환
- 난이도 중, 예상 분량 300~450줄. 게임별 기능 요구사항 15개, 비기능 요구사항 4개 (공통 요구사항 별도).

## 실험 목표(고정 화면 슈팅)

- 목적: 한 화면에 수십 개의 오브젝트(적, 방어벽 조각, 탄)를 두고 실행 중에 삭제하는 경우를 검증함. 스프라이트 시트 애니메이션과 그리기 순서도 함께 씀.
- 검증 기능: 키 입력, 대량 오브젝트와 실행 중 삭제, 사각형·원 충돌, 스프라이트 시트 부분 그리기와 프레임 전환, 그리기 순서, 효과음·배경음, 화면 전환
- 난이도 중, 예상 분량 350~500줄. 게임별 기능 요구사항 17개, 비기능 요구사항 4개 (공통 요구사항 별도).

## 실험 목표(2인 탱크 대전)

- 목적: 회전한 사각형끼리의 충돌, 카메라 뷰포트 분할과 미니맵, 두 사람의 키 세트를 검증함. 팩맨류가 쓰지 않은 카메라 기능을 가장 많이 씀.
- 검증 기능: 두 키 세트 액션 매핑, 회전 이동, 회전 사각형 충돌, 원-회전 사각형 충돌, 카메라 추적, 뷰포트 분할, 미니맵, 텍스처 공유(벽), 효과음·배경음, 화면 전환
- 난이도 중상, 예상 분량 400~550줄. 게임별 기능 요구사항 15개, 비기능 요구사항 4개 (공통 요구사항 별도).

## 실험 목표(미사일 방어)

- 목적: 마우스 조준과 화면↔월드 좌표 변환, 시간에 따라 크기가 바뀌는 원 충돌(폭발), 연쇄 폭발을 검증함. #35에서 보완한 런타임 색(폭발 원의 두 색 번갈아 쓰기)의 검증 대상이기도 함.
- 검증 기능: 마우스 위치·클릭, 레터박스에서의 좌표 변환, 커지고 줄어드는 원 충돌, 선 그리기(궤적), 연쇄 생성, 웨이브 정산, 효과음·배경음, 화면 전환
- 난이도 중, 예상 분량 300~450줄. 게임별 기능 요구사항 15개, 비기능 요구사항 4개 (공통 요구사항 별도).

## 실험 목표(서바이버류)

- 목적: 오브젝트 수가 가장 많은 게임으로, 카메라 추적과 넓은 월드, 원-원 다대다 충돌, 레벨업 선택 화면(마우스 클릭 판정)을 검증함. 많은 캐릭터가 텍스처 하나를 공유하면서 스프라이트 시트 칸을 바꿔 걷기·피격을 표현하는 것도 함께 봄. 성능 비교를 겸함.
- 검증 기능: 키·마우스 입력, 카메라 추적과 월드 경계, 대량 생성·삭제, 원-원 다대다 충돌, 스프라이트 시트 칸 전환·좌우 뒤집기·색 곱하기, 화면 고정 UI(체력·경험치 막대), 일시정지와 선택 화면, 점-사각형 판정, 배경음·효과음, 레터박스
- 난이도 중상, 예상 분량 480~700줄. 게임별 기능 요구사항 27개, 비기능 요구사항 6개 (공통 요구사항 별도).

## 검증 방법

- 채점은 채점표(`grading/sheets/`)의 항목 단위로 통과/실패를 기록함. 대상은 플레이로 확인할 수 있는 항목뿐이며, 나머지는 이유와 함께 `grading/sheets/items.csv`에 둠.
- 게임 완성 = 대상 항목 모두 통과. 통과율(통과 항목 ÷ 대상 항목)도 함께 기록함.
- 프레임 시간은 하니스가 무입력 실행 중에만 잼. 오브젝트가 많을 때의 성능은 #30 벤치마크에서 다룸.
- 무입력 실행: 입력 없이 30초 실행·녹화함. 10초 안에 비정상 종료가 없어야 하고, 게임별 기준(아래 절)에 맞는 동작이 보여야 함.
- 채점자는 조건(meno/SFML)을 모르는 상태에서 실행 파일을 직접 플레이함.
- LLM에게 주는 자료: 해당 게임의 요구사항 문서와 조건별 문맥 (두 조건 모두 공식 문서를 고치지 않고 줌. meno: README·사용 가이드 / SFML: readme·3.1 튜토리얼).
- 빌드에 실패하면 오류를 LLM에게 돌려주고 코드를 다시 받음 (최대 5왕복).

## 무입력 실행 기준 (1/2)

- 입력 없이 30초 실행·녹화하는 동안 다음 동작이 보여야 함.
  - 퐁: 약 4.5초에 CPU 첫 득점, 10초 안에 CPU 2점 이상
  - 스네이크: 약 4초에 오른쪽 벽 충돌 → 결과 화면
  - 플래피류: 약 2.5초에 바닥 충돌 → 결과 화면
  - 탑다운 슈터: 적이 다가와 3회 피격 → 20초 안에 결과 화면
  - 카드 짝 맞추기: 2초 뒤 보드 표시, 모두 뒷면, TIME 0.0 유지
  - 팩맨류: 약 6.5초에 첫 목숨, 약 15.5초에 결과 화면
- 시각은 실행 시작 기준의 근사값이며, 계산 근거는 rationale.md에 있음.

## 무입력 실행 기준 (2/2)

- 입력 없이 30초 실행·녹화하는 동안 다음 동작이 보여야 함.
  - 소행성 슈팅: 약 5~6초에 첫 충돌로 SHIPS 3 → 2
  - 고정 화면 슈팅: 약 4초에 첫 피격, 20초 안에 결과 화면
  - 2인 탱크 대전: 2초 뒤 두 화면과 미니맵에 탱크 표시, 이후 변화 없음
  - 미사일 방어: 약 10~18초에 첫 목표 파괴
  - 서바이버류: 적이 다가와 자동 사격에 처치되고, 30초 안에 HP 감소 (또는 그 전에 레벨업 카드에서 멈춤)
- 시각은 실행 시작 기준의 근사값이며, 계산 근거는 rationale.md에 있음.

## 주의 사항

- 명시되지 않은 요구사항은 채점하지 않음. 수업 요구사항 문서와 달리 암묵적 요구사항을 평가하지 않음.
- LLM은 질문할 수 없으므로, 명세에서 모호한 곳을 찾으면 실험 전에 문서를 고침.
- 게임별 명세는 서로 독립적임. 다른 미니게임 문서의 규칙을 가져다 쓰지 않음.
- LLM에게 하는 지시(수치·문자열 준수, 색과 그림, 모호할 때의 해석)는 각 게임 요구사항 문서의 '주의 사항'에 둠.
