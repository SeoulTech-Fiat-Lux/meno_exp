# 하니스·채점 운영 규칙

결정과 분석은 [PLAN.md](../PLAN.md), 명령은 [README.md](../README.md)에 있다.

## 1. 회차 실행

```
회차 = (모델, 게임, 조건, 반복). 전체 회차를 무작위로 섞은 순서로 돌린다.
프롬프트 = 지시문 + 조건 문맥(D2) + 템플릿 CMakeLists.txt(D8) + 게임 명세 md
for 왕복 in 1..5:
    응답 = 구독 CLI 호출 (harness/llm.py)
    코드 = 가장 긴 ```cpp 블록 (없으면 형식 오류 안내, 왕복 1회로 셈)
    main.cpp만 바꿔 빌드 (약 2초). 성공이면 끝, 실패면 컴파일 오류 앞 100줄을 돌려줌
빌드되면 30초 무입력 실행·녹화 → 프레임 시간 통계
회차 결과를 runs-*.jsonl에 한 줄 추가 (형식: harness/records.py)
```

**기록:** 회차 ID, 요청·응답 모델, 시각(UTC), 왕복 수, 빌드 성공과 실패 사유, 왕복별 토큰(입력·출력·추론·캐시),
코드 줄 수, 무입력 결과(종료 코드, 10초 안 종료, p95), meno·SFML 커밋, CLI 버전, 입력 파일 sha256, 실행 환경.
회차 폴더에는 프롬프트, 응답, main.cpp, 빌드 로그가 남는다. 녹화와 실행 파일은 git 밖에 둔다.

**토큰**
- 비교는 캐시와 무관한 원래 토큰으로 한다. 캐시는 CLI가 알아서 쓴다(시범에서는 입력의 99%가 캐시에서 읽힘).
- 문맥 토큰은 따로 재서 `runs/context_tokens.jsonl`에 둔다.
- 출력 토큰은 추론 토큰을 포함하며, 추론 토큰도 따로 기록한다.

## 2. 구독 CLI

| | Claude Code (`claude-cli`) | Codex (`codex-cli`) |
|---|---|---|
| 맡는 사람 | Claude Max 1인, 72회차 | ChatGPT Plus 2인, 18회차씩 (`--shard`) |
| 시스템 프롬프트 | `--system-prompt` ← `prompts/system.md` | `model_instructions_file` ← 같은 파일 |
| 도구 | `--tools ""`로 모두 끔 | 셸·웹 검색 끔, 읽기 전용. 생긴 호출은 `tool_calls`로 셈 |
| 사용자 설정 | `--safe-mode`, 빈 임시 폴더 | `--ignore-user-config`, 빈 임시 폴더. 전역 `AGENTS.md`가 있으면 멈춤 |
| 왕복 이어 가기 | `--resume <세션> --fork-session` | `codex exec resume <thread>` |
| 출력 상한 | `CLAUDE_CODE_MAX_OUTPUT_TOKENS` = 64000. 넘으면 잘린 왕복으로 세고 잘림 안내와 함께 다시 보냄 | 설정 불가. 잘린 답은 형식 오류가 됨 |
| 비용 | 없음. API 환산 비용만 기록 | 없음 |

- `--shard`는 게임 단위로 나눈다. 같은 (모델, 게임)의 두 조건이 같은 PC에서 돌아간다.
- 시범 전에 각자 `--probe`로 로그인, 세션 이어 가기, 토큰 기록, 도구 꺼짐을 확인한다.

## 3. 오류 처리

**회차를 다시 뽑지 않는다.** 결과를 보고 회차를 새로 받으면 실패한 표본이 다른 표본으로 바뀌어 결과가 좋은 쪽으로 치우친다.

| 상황 | 처리 |
|---|---|
| CLI 일시 오류 (시간 초과, 서버 오류) | 왕복으로 세지 않고 다시 보냄 (최대 `api_retries`번) |
| 사용 한도 | 30분마다 같은 왕복을 다시 보냄. 6시간 넘으면 멈추고, 같은 명령으로 이어서 돌림 |
| 문맥 창 초과, 공급자 거부 | 회차 실패(`context_window`, `refused`)로 기록하고 다음 회차 |
| 무입력 실행·통계 실패 | `noinput.harness_error`로 기록하고 계속 |
| 로그인 문제, CLI 명령줄 거부, 재시도 소진 | 하니스를 멈춤. 이어서 돌릴 때 끊긴 회차를 새로 받고 `attempt`로 기록 |

- **거부:** Claude Code의 종료 사유가 `refusal`일 때만 거부다. 코드 없이 설명만 있는 답은 형식 오류로 센다. Codex는 거부 신호가 없어 형식 오류로 집계된다.
- **생성 설정:** 온도 등은 모델 기본값을 쓰고 기록한다.
- **동결 확인:** 본 실행은 `freeze.lock.json`과 입력 해시가 같을 때만 시작한다. 시범과 mock은 입력 해시별 폴더에 기록한다.

## 4. 블라인드 채점

1. `grading/blind.py`가 빌드된 회차마다 무작위 ID 폴더를 만들고, 채점자 2명을 고르게 배정한다(채점자가 3명이면 1인당 전체의 2/3).
2. 대응표(ID ↔ 회차)는 저장소 밖에 두고, 채점이 끝날 때까지 아무도 열지 않는다. 가능하면 채점하지 않는 사람이 보관한다.
3. 채점자는 코드를 보지 않고 플레이하며 `sheet-<이름>.csv`에 통과·실패를 적는다.
4. 두 채점자가 어긋난 항목은 합의 회의에서 정한다.

**채점표 (`grading/sheets/<게임>.csv`)**
- 칸: `id, kind, section, requirement, result, note`. 플레이로 채점하는 항목만 있고, `requirement`는 채점자가 확인할 한 문장이다.
- 각 항목의 명세 원문, 채점하지 않는 항목(`how = harness`·`excluded`)과 그 이유는 `grading/sheets/items.csv`에 있다. 항목 ID는 LLM에게 주는 md에 넣지 않는다.
- 채점하지 않는 항목: 코드를 봐야 하는 것, 늘 지켜지는 것, 플레이로 볼 수 없는 것(내부 개수, 삭제 누락, px 크기), 일으키기 어려운 애매한 것, 다른 항목과 겹치는 것.

## 5. 확인한 것

기준 환경: Ubuntu 24.04.5, GCC 13.3.0, CMake 3.28.3.

| 항목 | 결과 |
|---|---|
| 템플릿 첫 빌드 (4코어) | meno 60초, SFML 53초 |
| `main.cpp`만 바꾼 재빌드 | 약 2초 |
| smoke 프로그램 | 두 조건 모두 정상 (`docs/smoke-*.png`) |
| 무입력 실행 | 종료 코드 124(시간 제한까지 생존). 오디오 장치 경고만 나옴 |
| 프레임 시간 p95 (Xvfb + llvmpipe) | meno 17.64ms, SFML 17.58ms. 절댓값보다는 조건 간 비교용 |
| 에셋 없음 / Esc | 종료 코드 1 / 0 |
| mock 실행 | 왕복 1 실패 → 오류 피드백 → 왕복 2 성공 → 무입력 실행 → 기록. 다시 실행하면 건너뜀 |
| 블라인드 묶음 | 무작위 ID 폴더에서 실행됨. 대응표를 저장소 안에 쓰려 하면 거부 |
| 동결 잠금 | 커밋 불일치·모델 미정이면 잠그지 않음. 명세 한 줄만 바꿔도 본 실행을 거부 |
| 잘린 답, 여러 코드 블록 | 전용 안내를 보내고 따로 집계. 조각과 전체 파일이 함께 오면 전체 파일을 빌드 |
| 동적 라이브러리 | 채점자 PC에는 런타임 패키지만 있으면 됨 (README) |
| 문맥 묶음 | meno 104KB, SFML 215KB. 다시 만들어도 바이트 단위로 같음 |
